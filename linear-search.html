🔦 Linear Search

The most natural way to find something: look at the first item, then the next, then the next… until you find it or run out.

Everyday picture: hunting for your house keys in a messy bag. You pull things out one at a time and check each. It works every time, needs no preparation, and doesn't care how messy the bag is — but a bigger bag takes longer.

Try it

Try a number that isn't in the list (type any number, like 100). Notice how every single box must be checked before we can be sure it's missing.

How it works

  1. Start at the first item.
  2. Is it the one you want? If yes, stop — you've found it.
  3. If not, move to the next item and repeat.
  4. If you reach the end without a match, the item isn't there.

In code (JavaScript)

function linearSearch(list, target) {
  for (let i = 0; i < list.length; i++) {
    if (list[i] === target) return i;   // found it
  }
  return -1;                            // not here
}

Real life

🔑 Keys in a bag
No order, no shortcut — check everything.
🔎 Ctrl+F in a document
The browser scans the text from the start for your word.
💎 list.include?(x)
Ruby's Array#include?, Python's x in list and JS's indexOf all do a linear search.

Time & space complexity

CaseStepsWhen
Best1 — O(1)It's the first item
Averagen/2 — O(n)Somewhere in the middle
Worstn — O(n)Last item, or not there at all
Extra memoryO(1)Just a counter — no copies of the list

For 1,000,000 items, the worst case is a million checks. That's fine once — painful if you do it thousands of times a second.

Use it when the list is small, or unsorted and you only search it once. It's also the only option for data you can't sort.
Avoid it when the data is big and you search repeatedly. Sort once, then use binary search — or use a hash table.
