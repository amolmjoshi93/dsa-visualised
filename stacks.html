🥞 Stacks

A pile where you can only touch the top. The last thing you put on is the first thing you take off.

Everyday picture: a stack of plates. You add a clean plate on top and you take the top plate when you need one. Nobody pulls a plate from the middle — the pile would fall over. This rule is called LIFO: Last In, First Out.

Try it: push and pop

top ↓
Push some plates, then pop them. Notice the order they come off.
Each operation takes 1 step, no matter how tall the stack is.

Real-life example: are the brackets balanced?

Compilers and code editors must check that every ( has a matching ), in the right order. A stack does this beautifully: push every opening bracket; when a closing bracket arrives, it must match the one on top.

Real life

↩️ Undo (Ctrl+Z)
Every edit is pushed on a stack. Undo pops the most recent one.
⬅️ Browser Back button
Pages you visit are pushed; Back pops the latest.
📞 Function calls
When code calls a function, it's pushed on the "call stack". When it returns, it's popped. (That's what a "stack overflow" is!)

Time & space complexity

n = number of items. Best / average / worst describe how lucky or unlucky the input is.

OperationBestAverageWorst
PushO(1)O(1)O(1)
PopO(1)O(1)O(1)
Peek at the topO(1)O(1)O(1)
Search for a valueO(1)O(n)O(n)
Space (storing n items)O(n)O(n)O(n)

Space: the stack grows by one slot per item, so n items cost O(n). Real programs have a limited "call stack" — recursing too deep fills it up and causes a stack overflow. The bracket checker above uses at most as many slots as there are opening brackets.

Use it when you need to remember things in order and go back through them newest-first.
