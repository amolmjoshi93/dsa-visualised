🌳 Trees

Data arranged as a hierarchy — one starting point at the top, branching downwards. A special kind, the binary search tree, finds things incredibly fast.

Everyday picture: the folders on your computer. One root folder, with folders inside folders. Or a family tree. Or a company's org chart: one CEO at the top, branching down.

Try it: a binary search tree

The rule: for every node, smaller values go to the left, bigger values go to the right. So at each node you can ignore half of what remains — just like binary search.

↔ Swipe sideways to see the whole diagram.

Insert a number, or search for one and watch the path it takes.

How it works

  1. Start at the root (the top node).
  2. Compare: is the number you want smaller or bigger than this node? Go left or right accordingly.
  3. Repeat until you find it, or hit an empty spot. An empty spot is exactly where a new value belongs when inserting.
  4. Height matters. A well-balanced tree of 1,000,000 items is only about 20 levels tall, so any search takes ≤ 20 steps. (A lopsided tree can degrade to a list — real databases use self-balancing trees to prevent that.)

Real life

📁 File systems
Folders inside folders — a tree.
🌐 The web page you're reading
HTML is a tree (the DOM): html → body → main → …
🗄️ Database indexes
When a database finds one row among millions in milliseconds, it's walking a tree (a B-tree).
🏢 Org charts, family trees, menus
Anything with "parent and children".
